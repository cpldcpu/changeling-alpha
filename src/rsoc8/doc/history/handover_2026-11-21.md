# Handover: rcore8 protocol emulator, from design and verification to physical implementation

Date: 21 November 2026. Owner: Tim S. B. (GitHub: cpldcpu). State: specification draft 0.36, verification report issue 2.

This document is for the agent that takes the design into the Tiny Tapeout flow in another environment. It says
what you receive, what is finished, what you must not change without asking, and what to do first. Read it
completely before you start. Where it and the specification disagree, the specification is right; report the
disagreement.

## 1. What the chip is

An entry for the Jane Street ASIC competition: a protocol emulator on IHP 130 nm (SG13 CMOS, 5 metal layers)
through Tiny Tapeout, area 8x4 tiles (32 tiles), reference clock 60 MHz, deadline 18 January 2027. Required
protocols: UART, SPI, I2C. Stretch protocols: USB low-speed, 10BASE-T, WS2812, each in both roles.

Architecture: two 8-bit cores (`rcore8d`, reduced AVR instruction set of the ATtiny40 class, programmed with
stock avr-gcc), each with its own code SRAM of 1024 x 16 bit, a shared data SRAM of 1024 x 16 bit used byte-wise
(2 KB), a shared register bus with an arbiter, 8 bidirectional line pins, two pairs of "line cells" that do the
bit-level work of serial protocols, event flags, timer, PWM, CRC unit, a clocking block with an internal
oscillator and trim loop, and an SPI host link for loading and debugging. The chip has no non-volatile memory:
a host loads the program after reset.

## 3. Top level, pins, clock, reset

Top module: `tt_um_cpldcpu_rpe` with the port names of the Tiny Tapeout template (`ui_in`, `uo_out`, `uio_in`,
`uio_out`, `uio_oe`, `ena`, `clk`, `rst_n`).

| Pins | Function |
|---|---|
| `ui_in[0]`, `[1]`, `[2]` | host link clock, chip select (active low), data in (SPI mode 0, sampled with the system clock; host clock at most system clock / 8) |
| `ui_in[3]` | clock source strap: 0 external clock, 1 internal oscillator |
| `ui_in[4]` | reference input for the trim counter |
| `ui_in[5..7]` | inputs |
| `uo_out[0]` | host link data out |
| `uo_out[1]`, `[2]` | clock output, debug signal (port outputs while not enabled) |
| `uo_out[3..4]`, `[5..7]` | outputs; 5 to 7 also PWM |
| `uio[7:0]` | bidirectional port for the line cells |

The pin positions have NOT been checked against the Tiny Tapeout conventions for this shuttle (for instance
fixed positions for SPI or UART on the demo board). Check and report before changing anything.

Clock and reset:

- `clk` is the external 60 MHz clock. `rst_n` is asynchronous, active low; each clock domain releases reset
  through its own two-stage synchroniser.
- There are two source clocks, the external one and the oscillator (`rpe_osc`, 15 MHz nominal). They are
  asynchronous to each other. `rclk_src` selects one without glitches: each source has an enable chain and a
  clock gate, and the system clock is the OR of the two gated clocks (`assign clk = gext | gosc`).
- Falling clock edges are used on purpose in two places: the gate enables in `rclk_src`, and the falling-edge
  input samples in `rlcports.v` (10BASE-T reception samples the pins on both edges).
- The cores have a clock enable from a divider (`CLKCDIV`), the peripherals another (`CLKPDIV`). The line cells
  normally run at the full rate.
- Configuration registers are written through clock gates, one per register (`rlc_cg`, 81 gates in the
  synthesis). With the define `IHP_CELLS` the gate is the library cell `sg13g2_lgcp_1`; without it a
  behavioural latch gate is used for simulation.

Defines: `SIM` (simulation only code in the core), `FUNCTIONAL` (for the foundry SRAM model), `IHP_CELLS`
(library clock gate), `OSCMODEL` (testbench only).

## 4. Macros

- Three instances of `RM_IHPSG13_1P_1024x16_c2_bm_bist` through `rpe_mem`: code memory 0, code memory 1, data
  memory. BIST pins are tied off. The data memory uses the bit mask for byte writes.
- From the IHP liberty file (slow corner): clock-to-output 7.0 to 7.4 ns (4.2 to 4.5 ns typical). At 60 MHz this
  leaves about 9.2 ns for the path behind the macro output.
- The oscillator macro does not exist. `rpe_osc` (ports `en`, `trim[7:0]`, `clk`) is a stub. With the stub the
  strap pin must select the external clock. If the oscillator macro is not ready in time, the chip is
  submitted with the stub.

## 5. Numbers from the logic synthesis (yosys, IHP standard cells, macros as black boxes)

14,308 cells, 2,058 flip-flops, 87 clock gating cells, 221,326 um2 of cell area (measured on the RTL of this
package, draft 0.36). At 60 % utilisation this is about 11.8 tiles; with
8.7 tiles for the three macros and their keep-out, about 20.5 of 32 tiles before the oscillator and routing
between macros and logic. The script is `syn/syn_top.ys` (paths to the liberty files have to be adapted).
This synthesis reports no path delays. No timing number of this design is measured.

## 6. What is finished and what is not

Finished: RTL of all digital blocks; block-level and top-level verification by simulation (see the verification
report); firmware for all six protocols, a USB HID device with enumeration, an I2C sensor bridge, a 10BASE-T
ping endpoint.

Not finished, and yours or the owner's to do:

1. Static timing at 60 MHz. Expected longest paths: code SRAM output through decode, register file and pointer
   adder to the data SRAM address input; and the bus request through the arbiter. If 60 MHz is not met, the
   cores can run at a divider (30 MHz) with the line cells at 60 MHz: report the achievable frequency per path
   group (core paths, peripheral paths) so that this decision can be made. Do not restructure the RTL for
   timing without asking.
2. Placement of the three macros in the 8x4 area, power hookup of the macros, routing channels.
3. Clock tree: the flow must keep the two clock gates and the OR gate of `rclk_src` as written, build the tree
   behind the OR, and treat the two source clocks as asynchronous. The register clock gates must stay gates.
4. Constraints: two clocks (external 16.67 ns; oscillator 66.7 ns nominal; its range before trimming is not known until the macro exists, the model assumes 0.5 % per trim step),
   asynchronous to each other; synchronisers in `rclk_src`, `rclk_ctl` (presence and reference inputs),
   `rlcports.v` (pins) and `rhost.v` (host link pins); the falling-edge samples in `rlcports.v` are half-cycle
   paths that must be timed, not ignored.
5. Gate-level simulation of at least the base regression subset named in section 8.
6. Pin positions (section 3), `info.yaml`, documentation required by Tiny Tapeout.
7. The oscillator macro (analog, owner).

## 7. Rules

1. Do not change the behaviour of the RTL. If the flow needs a change (a cell instantiation, a reset style, a
   wrapper), make the smallest change, keep it in a separate patch, and run the suites of section 8 before and
   after. Report every change.
2. The hardware changes C1 to C6 of specification section 18.5 (framing checks, end sequence, underrun bit, second cell
   event, time base prescaler) are specified and NOT implemented. Do not implement them unless the owner asks.
   If asked: the behavioural model of the line cell (`linecells` package, `model/linecell.py`) gets the rules
   first, then the RTL, then all suites.
3. A test result counts only if you ran it. Report commands and output lines. If something fails, report the
   failure with its output; do not change an expectation to make it pass.
4. Report numbers with units and say whether a number is measured or estimated.
5. Write plain, literal prose in reports. In documents the owner is named "Tim S. B. (GitHub: cpldcpu)".

## 8. First steps, in this order

1. Unpack `rsys_rtl.tar.gz` and run `sh tests/run_fw.sh` in `rsys`. Needed: Icarus Verilog, Python 3, avr-gcc
   with avr-libc (device `attiny40`). Expected: every line ends with `EXIT 0`, `PASS` or `USB PASS`; exactly one
   line is expected to end with `EXIT 110` (it says so). About 20 minutes. If your tool versions give a
   different result, stop and report.
2. Run `sh tests/run_models.sh` (2 minutes): `0 mismatching` for the five blocks.
3. Run the logic synthesis of your flow on the unchanged RTL with `IHP_CELLS` defined and compare cell count
   and area with section 5.
4. First hardening run without timing pressure, to get: achievable clock period, utilisation, macro placement.
   Report these before optimising.
5. Gate-level simulation with the same testbench (`tb/tb_sys.v`, the top module name is unchanged): at least
   `fw1`, `fw2`, `fw6`, `fw11`, `fw12`, the host link test (`+htest=1`), and `fwusb` with `+usbhost +quick`.
   Command lines are in `tests/run_fw.sh`.

Subset for a quick check after any change (a few minutes, not measured as a set): the lines for `fw1`, `fw2`, `fw6`, `fw10`, `fw11`,
`fw12`, `fw13`, `fw14` and the host link test in `tests/run_fw.sh`, plus `tests/run_models.sh`.

## 9. Things that cost time before

- The system testbench runs the external clock with a period of 10 ns, not 16.67 ns. Count in clock cycles.
  Only the tests on the oscillator model (`tb/osc_model.v`, define `OSCMODEL`, plusarg `+oscusb`) use real time.
  For gate-level simulation with timing you have to set the real period; the protocol models take their bit
  times in clock cycles or have a bit-time variable (`ubit`, `devbit` in `tb/usb_host.v`).
- Icarus Verilog does not re-evaluate a continuous assignment that calls a function reading module-level
  signals; all inputs of such functions are passed as arguments in this RTL. Keep it that way.
- The USB and sensor tests take 2 to 3 minutes each; several test scripts rebuild `build/tb_sys.vvp`. Do not
  run two suites in the same directory at the same time.
- avr-gcc for this core: function arguments only in r25..r20, no LDD, no ADIW, LDS/STS reach only 0x40 to 0xBF;
  use `PROT_WRITE(reg, val)` for protected registers; images for core 1 include `fw/rpe_core1.h` and are built
  with core argument 1; large buffers go to `.noinit`.
- Code memory is 2,048 bytes per core image. An image for one core (`+hex=`) may continue in the code memory of
  core 1 (up to 4,096 bytes).
- A host access to memory or registers needs both cores halted. This is a property of the design.

## 10. Known limits of the design as delivered

Each has a tested workaround or a documented restriction; details in specification section 18.4.

- One receive cell does not check the UART stop bit or validate the start bit (workaround: second receive cell).
- The transmit cell has no underrun indication (SPI slave: firmware must supply the next byte in time).
- 10BASE-T: the idle pulse at the frame end works single-ended only, by a firmware workaround; no link pulses.
- USB from the internal oscillator: firmware must check the frame time; the coarse trim needs frames without
  packets.
- USB device stack: passes at a core clock of 15 MHz and above, fails at 10 MHz.
